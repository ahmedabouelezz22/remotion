# دليل التشغيل — موقع مكتب أبو العز للمحاماة

مكتوب لغير المبرمج. كل إجراء هنا خطوات مرقّمة يمكن تنفيذها من المتصفّح.
ما يحتاج سطر أوامر مُعلَّم بذلك صريحاً.

---

## 1) خريطة سريعة: أين يُعدَّل كل شيء

| ما تريد تغييره | الملف أو المكان |
|---|---|
| أسعار المتجر وأوصاف المنتجات | `src/content/products.ts` |
| بيانات المكتب والهاتف والبريد | `src/content/site.ts` |
| مقالات المدونة | `src/content/blog.ts` |
| المكتبة القانونية | `src/content/library.ts` |
| الخدمات | `src/content/services.ts` |
| الأسئلة الشائعة | `src/content/faq.ts` |
| نماذج العقود | `content/templates/*.md` |
| **نشر منتج أو سحبه** | من اللوحة: `/admin/products` — بلا نشر جديد |
| **تأكيد موعد أو إلغاؤه** | من اللوحة: `/admin/bookings` |
| **تأكيد تحويل بنكي** | من اللوحة: `/admin/orders` |
| المفاتيح والأسرار | إعدادات الاستضافة ← Environment Variables |

تعديل أي ملف محتوى يحتاج نشراً جديداً. ما في اللوحة يسري فوراً.

---

## 2) النسخ الاحتياطي

### أ) قاعدة البيانات — وهي ما لا يمكن تعويضه

الطلبات والحجوزات والاشتراكات والرسائل كلها في PostgreSQL. المحتوى
(المقالات والنماذج) في Git ولا يحتاج نسخاً منفصلاً.

**الأسهل**: فعّل النسخ التلقائي من مزوّد القاعدة.

| المزوّد | المكان | الخطّة المجّانية |
|---|---|---|
| Neon | Project → Branches → Point-in-time restore | 7 أيام استرجاع |
| Supabase | Project → Database → Backups | نسخة يومية |
| Vercel Postgres | Storage → Database → Backups | حسب الخطّة |

**نسخة يدوية** (تحتاج سطر أوامر، مرّة شهرياً يكفي):

```bash
pg_dump "$DATABASE_URL" --no-owner --format=custom > abz-$(date +%F).dump
```

احفظ الملف خارج الاستضافة (قرص خارجي أو Google Drive). الملف يحتوي
بيانات عملاء، فلا يُشارك ولا يُرفع إلى مكان عامّ.

### ب) ملفات المنتجات الرقمية

`private/downloads/` مُستثنى من Git لأن ملفّاته مولَّدة. حزمة نماذج
العقود تُبنى تلقائياً من `content/templates/` عند كل نشر
(`npm run build:downloads`)، فمصدرها محفوظ في Git. أي ملف رقمي آخر
تضيفه يدوياً **ليس له نسخة** — احفظه عندك.

---

## 3) التراجع عن نشر أضرّ بالموقع

### أ) التراجع الفوري من لوحة Vercel (دقيقة واحدة، بلا سطر أوامر)

1. افتح [vercel.com](https://vercel.com) ← المشروع ← **Deployments**
2. اختر آخر نشر كان يعمل (الأخضر الذي قبل المشكلة)
3. زرّ `⋯` ← **Promote to Production** ← تأكيد

الموقع يعود إلى تلك النسخة فوراً. **لا يُعيد هذا قاعدة البيانات**: لو كان
النشر الجديد قد عدّل بيانات فالتراجع لا يمحو تعديله.

### ب) التراجع عن تغيير في الكود

```bash
git revert <معرّف-الcommit>   # يُنشئ تغييراً يُلغي الأول، ولا يمحو التاريخ
git push
```

لا تستخدم `git reset --hard` ولا `--force` على فرع مشترك.

### ج) التراجع عن ترحيل قاعدة بيانات

الترحيلات هنا **إضافية فقط**: كل جملة `CREATE TABLE IF NOT EXISTS` أو
`ADD COLUMN IF NOT EXISTS`، فلا يحذف النشر عموداً ولا جدولاً ولا يفقد
بيانات. التراجع عن الكود كافٍ؛ الجداول الزائدة تبقى بلا ضرر.

## 4) أعطال شائعة وما تفعله

### «الإشعارات لا تصلني»

1. افتح `/admin/notifications?only=failures` — هذه أول خطوة دائماً
2. اقرأ عمود «الخطأ»:

| الخطأ | المعنى | الحل |
|---|---|---|
| «لم يُضبط أي مزوّد واتساب» | لا مفاتيح واتساب | اضبط `ULTRAMSG_*` أو `META_WA_*` أو `TWILIO_*` |
| «لم يُضبط بوت تيليجرام» | تلجرام غير مضبوط (اختياري) | تجاهله أو اضبط `TELEGRAM_*` |
| رسالة من مزوّد البريد | البريد مرفوض | تحقّق من المفتاح وتوثيق النطاق (SPF/DKIM) |
| لا قيود إطلاقاً | لا يصل الطلب للخادم | تحقّق من `DATABASE_URL` ومن Vercel ← Logs |

3. الرسائل محفوظة في `/admin/messages` والحجوزات في `/admin/bookings`
   حتى لو فشل الإشعار — **لا يضيع عميل بسبب إشعار فاشل**

### «عميل دفع ولم يصله رابط التحميل»

1. `/admin/orders` ← ابحث بمرجع الطلب
2. إن كانت الحالة «مدفوع»: المشكلة في البريد. راجع
   `/admin/notifications` بنفس المرجع
3. إن كانت «بانتظار الدفع» والمال وصل فعلاً: استخدم **تأكيد تحويل**
   وأدخل رقم العملية. هذا يُصدر الرابط ويرسله
4. لا تُعلّم طلباً مدفوعاً إلا وأنت ترى المبلغ في حسابك

### «الموقع لا يفتح»

1. Vercel ← Deployments: هل آخر نشر أحمر؟ ← اقرأ Build Logs
2. هل أخضر والموقع لا يفتح؟ ← Vercel ← Logs (Runtime)
3. «خدمة الحساب غير مهيّأة» ⇒ `AUTH_SECRET` أو `DATABASE_URL` ناقص
4. لا حلّ سريع؟ ← تراجَع (الفقرة 3-أ) ثم شخِّص بهدوء

### «اللوحة تقول: غير مهيّأة»

`OWNER_EMAILS` غير مضبوط. اضبطه في متغيّرات البيئة على بريدك وأعِد النشر.

### «رابط الدخول لا يعمل»

الرابط لمرّة واحدة ولمدة 20 دقيقة — بعد أول فتح أو بعد انقضاء المدة يجب
طلب رابط جديد. هذا مقصود: رابط يُعاد استخدامه يعني أن من يقرأ بريدك يدخل
حسابك.

### «موعد محجوز وأنا أراه فارغاً»

القاعدة تمنع حجز موعدين في وقت واحد. إن ألغيت الحجز من اللوحة تحرّر
الوقت فوراً وظهر متاحاً في صفحة الحجز.

## 5) المهمّة اليومية (الاشتراكات)

تعمل تلقائياً كل يوم 06:00 UTC عبر Vercel Cron. تفعل:

1. تذكير العملاء قبل انتهاء الاشتراك بـ7 و3 ويوم (تذكير واحد لكل عتبة)
2. مدّ اشتراكات PayPal التي جُدِّدت تلقائياً
3. تعليم ما لم يُجدَّد «متأخّر السداد» وإشعار العميل والمكتب
4. إلغاء ما طُلب إيقاف تجديده عند نهاية دورته
5. تنظيف رموز الدخول المنتهية

**للتحقّق**: Vercel ← Logs ← ابحث `cron/subscriptions`. ملخّص يومي يصل
بريد المكتب إن كان هناك ما يُبلَّغ عنه.

**تشغيلها يدوياً** (مثلاً للاختبار):
`https://aboelezzlaw.com/api/cron/subscriptions?secret=<CRON_SECRET>`
ولا تُشارك هذا الرابط مع أحد.

---

## 6) إضافة مالك ثانٍ أو سحب صلاحية

`OWNER_EMAILS` يقبل عدّة عناوين مفصولة بفاصلة:

```
OWNER_EMAILS=aboelezzlawfirm@gmail.com,manager@aboelezzlaw.com
```

لسحب صلاحية: احذف العنوان وأعِد النشر. الجلسة القائمة تسقط عند أول طلب
بعد النشر لأن التفويض يُفحص في كل طلب، لا عند الدخول فقط.

---

## 7) ما لا تفعله

- **لا تضع مفتاحاً أو سرّاً في الكود** ولو مؤقّتاً — Git يحفظ التاريخ
  ولا يُمحى. الأسرار في متغيّرات بيئة الاستضافة فقط.
- **لا تُعلّم طلباً مدفوعاً** قبل أن ترى المبلغ. تأكيد دفع كاذب يُصدر
  منتجاً ويُفعّل اشتراكاً.
- **لا تنشر منتجاً** قبل أن تراجع محتواه. العميل يشتري ما تعرضه.
- **لا تستخدم نفس القيمة** لأكثر من سرّ. كل سرّ قيمة مستقلّة.
- **لا تُشارك رابط الـ cron** ولا `CRON_SECRET`.
- **لا تُشارك نسخة قاعدة البيانات** — فيها بيانات عملاء.
