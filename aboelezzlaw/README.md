# مكتب أبو العز للمحاماة — الموقع الإلكتروني

موقع مبنيّ بالكود بالكامل ليحلّ محلّ نسخة Hostinger Horizons. عربي بالكامل واتجاه RTL،
مبنيّ بـ **Next.js 15 (App Router) + TypeScript + Tailwind CSS 4**.

> **الخلاصة:** كل ما كان «لا يعمل» في النسخة السابقة صار يعمل فعلياً — النماذج تُرسل إشعارات
> حقيقية إلى بريدك وواتساب، والمتجر يقبل الدفع، والمكتبة والفيديوهات والمدونة محتوى حقيقي.

---

## ما الذي كان معطّلاً ولماذا

فحصتُ كود الموقع السابق، وهذه أسباب الأعطال بالضبط:

| العطل | السبب في الكود القديم | الحل هنا |
|---|---|---|
| نموذج «اتصل بنا» لا يصلك | `ContactPage.jsx` كان يحفظ الرسالة في `localStorage.setItem('contactMessages', …)` — أي في متصفّح الزائر نفسه، ولا يغادرها إطلاقاً | `POST /api/contact` يرسل إلى بريدك + واتساب + تيليجرام معاً |
| «حجز استشارة» لا يصلك | `BookingPage.jsx` نفس المشكلة تماماً: `localStorage.setItem('bookings', …)` | `POST /api/booking` + مُنتقي مواعيد يحترم أيام العمل |
| الدفع غير مكتمل | `addToCart` كان يعرض إشعاراً نصّه «🚧 قيد التطوير» فقط | طبقة دفع كاملة: Paymob + PayPal + تحويل يدوي/Wise/إنستاباي |
| المكتبة لا تعمل | زر التحميل كان يعرض «قيد التطوير» | 12 مرجعاً مفتوح المصدر بروابط رسمية تعمل |
| الفيديوهات وهمية | قائمة مكتوبة يدوياً بلا روابط حقيقية | تُجلب تلقائياً من قناتك عبر تغذية RSS |
| المدونة بلا محتوى | 6 مقالات عناوين فقط، بلا صفحات تفاصيل | 6 مقالات كاملة موثّقة بمصادرها الرسمية |
| لوحة التحكم وهمية | `DashboardPage` كانت تعرض بيانات ثابتة مكتوبة في الكود | لوحة حقيقية بدخول بلا كلمة مرور وسجلّ طلبات ومواعيد واشتراكات |
| الطلبات لا تُحفظ | لا قاعدة بيانات أصلاً | PostgreSQL مع جداول تُنشأ تلقائياً |
| الاشتراكات بلا تجديد | الباقات كانت زر «قيد التطوير» | تجديد تلقائي عبر PayPal + محرّك تذكيرات يومي |

## التشغيل محلياً

```bash
cd aboelezzlaw
npm install
cp .env.example .env.local     # ثم املأ القيم المطلوبة
npm run dev                    # http://localhost:3000
```

الموقع **يعمل بدون أي متغيّر بيئة**، لكن النماذج لن تُرسل إشعارات والدفع سيقتصر على
التحويل اليدوي. راجِع القسم التالي.

## ⚡ أسرع طريق لجعل الإشعارات تعمل (10 دقائق)

هذا أهم قسم في الملف. اتبعه بالترتيب.

### الخطوة 1 — البريد الإلكتروني (إجباري)

**الخيار الأسهل — Resend:**

1. سجّل مجاناً على [resend.com](https://resend.com) (3000 رسالة شهرياً مجاناً).
2. من **API Keys** أنشئ مفتاحاً جديداً وانسخه.
3. ضع في `.env.local`:
   ```
   RESEND_API_KEY=re_xxxxxxxxxxxx
   MAIL_FROM="Abo Elezz Law <onboarding@resend.dev>"
   ```
4. لاحقاً وثّق نطاق `aboelezzlaw.com` داخل Resend، ثم غيّر المُرسِل إلى
   `"مكتب أبو العز <no-reply@aboelezzlaw.com>"` — هذا يحسّن وصول الرسائل كثيراً.

**البديل — Gmail عبر SMTP:**

1. فعّل «التحقّق بخطوتين» على حساب `aboelezzlawfirm@gmail.com`.
2. من [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) أنشئ
   **«كلمة مرور تطبيق»**.
3. ضع في `.env.local`:
   ```
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=587
   SMTP_USER=aboelezzlawfirm@gmail.com
   SMTP_PASSWORD=كلمة-مرور-التطبيق-المكوّنة-من-16-حرفاً
   MAIL_FROM="مكتب أبو العز <aboelezzlawfirm@gmail.com>"
   ```

> ⚠️ **لا تستخدم كلمة مرور جيميل العادية** — لن تعمل وقد يُقفل حسابك.

### الخطوة 2 — إشعار واتساب على `01157844664`

**الخيار العملي — UltraMsg** (يرسل رسائل حرّة بلا قوالب معتمدة، وهو الأنسب لحالتك):

1. سجّل على [ultramsg.com](https://ultramsg.com) وأنشئ Instance.
2. اربط رقم واتساب بمسح رمز QR (يُفضّل رقم عمل منفصل، لا رقمك الشخصي).
3. انسخ `Instance ID` و `Token` وضعهما:
   ```
   ULTRAMSG_INSTANCE_ID=instance12345
   ULTRAMSG_TOKEN=xxxxxxxxxx
   ```

**البديل المجاني تماماً — تيليجرام** (يصل فوراً على هاتفك، وأنصح بتفعيله بجانب واتساب):

1. راسل [@BotFather](https://t.me/BotFather) على تيليجرام واكتب `/newbot`.
2. انسخ التوكن الذي يعطيك إياه.
3. أرسل أي رسالة إلى بوتك الجديد، ثم افتح في المتصفّح:
   `https://api.telegram.org/bot<التوكن>/getUpdates` وانسخ قيمة `chat.id`.
4. ضعهما:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC-xxxx
   TELEGRAM_CHAT_ID=987654321
   ```

> النظام يرسل على **كل القنوات المضبوطة في آن واحد**. فشل قناة لا يمنع الأخريات، ولا يُظهر
> خطأً للزائر ما دامت قناة واحدة نجحت. وكل بريد إشعار يحتوي زرّ **«الرد على العميل عبر واتساب»**
> يفتح محادثة مع العميل مباشرةً بنقرة واحدة.

### الخطوة 3 — اختبر فعلياً

شغّل `npm run dev`، افتح `/contact`، املأ النموذج وأرسله. يجب أن يصلك:
- بريد على `aboelezzlawfirm@gmail.com` بعنوان `[أبو العز للمحاماة] رسالة جديدة من نموذج «اتصل بنا»`
- رسالة واتساب و/أو تيليجرام
- ويصل العميل بريد تأكيد تلقائي

إن لم يصل شيء، راجِع **Vercel ▸ Logs** (أو الطرفية محلياً) — يُسجَّل سبب الفشل بالتفصيل.

## بوابات الدفع

### الوضع الحالي (يعمل الآن بلا أي حساب بوابة)

**التحويل اليدوي** مفعَّل افتراضياً. اضبط بياناتك:

```
BANK_TRANSFER_DETAILS="البنك الأهلي المصري | اسم الحساب: ... | رقم الحساب: ... | IBAN: ..."
INSTAPAY_ADDRESS="aboelezz@instapay"
WISE_DETAILS="الاسم: Ahmed Aboelezz | البريد: ..."
WALLET_NUMBER="01157844664 (فودافون كاش)"
```

بعد الطلب يرى العميل هذه البيانات مع رقم طلبه، ويصلك أنت إشعار فوري بالطلب.

### PayPal (يمكنك تفعيله اليوم — عندك حساب بالفعل)

1. من [developer.paypal.com](https://developer.paypal.com/dashboard/) أنشئ تطبيقاً.
2. انسخ `Client ID` و `Secret`.
3. ضع:
   ```
   PAYPAL_CLIENT_ID=...
   PAYPAL_CLIENT_SECRET=...
   PAYPAL_ENV=sandbox     # غيّرها إلى live بعد الاختبار
   PAYPAL_CURRENCY=USD
   PAYPAL_EGP_RATE=50     # سعر التحويل — حدّثه دورياً
   ```

> باي بال **لا يدعم الجنيه المصري**، لذلك يحوّل النظام المبلغ إلى الدولار وفق `PAYPAL_EGP_RATE`.
> راجِع هذا الرقم كل فترة حتى لا تخسر فرق العملة.

### Paymob (فور اعتماد حسابك)

1. من لوحة Paymob: **Settings ▸ API Keys** انسخ `Secret Key` و `Public Key`.
2. من **Payment Integrations** انسخ أرقام التكاملات (بطاقة، محفظة…).
3. من **Settings ▸ Account Info** انسخ `HMAC Secret`.
4. ضع:
   ```
   PAYMOB_SECRET_KEY=...
   PAYMOB_PUBLIC_KEY=...
   PAYMOB_INTEGRATION_IDS=1234567,7654321
   PAYMOB_HMAC_SECRET=...
   ```
5. في لوحة Paymob اضبط **Transaction Processed Callback** على:
   `https://aboelezzlaw.com/api/payments/paymob/webhook`

> ⚠️ **راجِع توثيق Paymob بعد فتح الحساب** للتأكد من أرقام التكاملات ومن ترتيب حقول توقيع
> الـ HMAC — فقد تُحدّثه Paymob. ترتيب الحقول المعتمد موجود في
> `src/lib/payments/paymob.ts` في الثابت `HMAC_FIELD_ORDER`.
>
> الـ webhook **يرفض** أي إشعار لا يحمل توقيعاً صحيحاً — بدون هذا التحقّق يستطيع أي شخص
> انتحال إشعار «دفعة ناجحة» والحصول على منتجاتك مجاناً.

## قاعدة البيانات ولوحة تحكم العميل

### لماذا تحتاجها

بدون قاعدة بيانات يظل الموقع يعمل بالكامل وتصلك كل الإشعارات — لكن تختفي أربع قدرات:

- **لوحة تحكم العميل**: سجلّ طلباته ومواعيده واشتراكاته وروابط تحميله.
- **منع الحجز المزدوج**: بدونها قد يحجز شخصان نفس الموعد.
- **سجلّ الطلبات**: البحث عن طلب قديم برقمه.
- **تتبّع الاشتراكات**: مواعيد التجديد والتذكيرات.

### الإعداد (5 دقائق، مجاناً)

1. سجّل على [neon.tech](https://neon.tech) وأنشئ مشروعاً (الخطة المجانية تكفي تماماً).
2. انسخ **Connection String** — اختر نسخة **Pooled** لأن الدوال بلا حالة.
3. ضعها في `DATABASE_URL`.
4. ولّد مفتاح توقيع الجلسات:
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
   وضعه في `AUTH_SECRET`.

الجداول تُنشأ تلقائياً عند أول طلب — لا هجرات ولا أوامر SQL يدوية.

> على Vercel يمكن ربط Neon بنقرة واحدة من **Storage ▸ Create Database**، ويُضاف
> `DATABASE_URL` إلى المشروع تلقائياً.

### كيف يدخل العميل

لا كلمات مرور إطلاقاً. العميل يدخل بريده في `/account`، فيصله رابط دخول صالح 20 دقيقة.
بعد فتحه تُنشأ جلسة موقّعة تدوم 30 يوماً.

**لماذا هذا التصميم؟** لأن تخزين كلمات مرور العملاء مسؤولية أمنية وقانونية بلا مقابل هنا:
العميل يحتاج فقط الاطّلاع على طلباته. الرابط المؤقّت يُثبت ملكية البريد وهو كل المطلوب،
ولا يوجد ما يُسرق إن اختُرقت القاعدة.

الجلسة كعكة موقّعة بـ HMAC ولا تُخزَّن في القاعدة — فلا استعلام لكل طلب، ولا يمكن تزوير
الجلسة دون معرفة `AUTH_SECRET`.

## الاشتراكات والتجديد التلقائي

### مستويان من التجديد

**المستوى الأول — تجديد تلقائي حقيقي (PayPal).** أنشئ خطة لكل باقة في لوحة PayPal ثم
اربطها في `PAYPAL_PLANS`:

```
PAYPAL_PLANS={"package-basic":"P-1AB...","package-business":"P-2CD...","package-premium":"P-3EF..."}
```

عندها يُحصَّل الاشتراك تلقائياً كل دورة، ويستطيع العميل إيقافه بنفسه من صفحة حسابه
(ويُلغى لدى PayPal فوراً حتى لا يستمر الخصم).

**المستوى الثاني — تجديد بتذكير (بلا خطط).** إن لم تُضبط الخطط تُباع الباقة كدفعة واحدة،
ويتولّى محرّك التذكيرات إشعار العميل قبل 7 و3 ويوم واحد من انتهاء دورته، ثم يُعلَّم
الاشتراك «متأخّر السداد» ويصلك ملخّص يومي بمن يحتاج تجديداً.

### تشغيل المحرّك

الجدولة معرّفة في `vercel.json` (يومياً 6:00 صباحاً UTC). يتبقّى ضبط `CRON_SECRET`
لحماية المسار — بدونه يرفض المسار كل استدعاء بـ 401.

للاختبار يدوياً:

```bash
curl "https://aboelezzlaw.com/api/cron/subscriptions?secret=<CRON_SECRET>"
```

> **قيد مقصود:** الاشتراك لا يُخلط بمنتجات أخرى في طلب واحد، ويرفض الخادم ذلك برسالة
> واضحة. السبب أن البوابة تُنشئ جدول تحصيل دورياً للطلب كله، فينتهي العميل «مشتركاً»
> في كتاب مطبوع.

## بيع المنتجات الرقمية

ولّد أولاً مفتاح توقيع روابط التحميل وضعه في `DOWNLOAD_SECRET`:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### حزمة نماذج العقود — جاهزة ومبنية آلياً

النماذج الاثنا عشر مكتوبة كـ Markdown في `content/templates/`، ويحوّلها سكربت البناء إلى
ملفات Word عربية (RTL) مضغوطة في `private/downloads/contract-templates-pack.zip`:

```bash
npm run build:downloads
```

ويُنفَّذ هذا تلقائياً ضمن `npm run build`، فتُبنى الحزمة عند كل نشر.

**لتعديل نموذج:** حرّر ملف الـ Markdown وادفع التغيير — لا تحرّر ملفات `.docx` الناتجة
فهي تُستبدل عند كل بناء.

> ### ⚠️ راجِع النماذج قبل بيعها
> النماذج مصاغة صياغة مهنية لكنها **أدوات عمل لا عقود جاهزة**، وكل ملف يحمل صفحة غلاف
> تقول ذلك صراحةً. بصفتك محامياً، راجِعها وكيّفها على ممارستك قبل طرحها للبيع، ثم احذف
> تنبيه الغلاف من `scripts/build-downloads.mjs` (دالة `coverPage`) إن أردت.

### منتج معلن ولم يُرفع ملفه

كتاب الزكاة (النسختان الإلكترونية والمطبوعة) معلَّم بـ `comingSoon: true` في الكتالوج،
فيُعرض بوسم «قريباً» ولا يُضاف إلى السلة **ويرفضه الخادم عند الدفع** — فلا يدفع أحد ثمن
ملف غير موجود. بعد رفع `private/downloads/zakat-guide.pdf` احذف العلامة.

### لماذا خارج `public/`؟

أي ملف داخل `public/` يمكن تنزيله بمعرفة رابطه — أي بلا دفع. الملفات هنا لا تُقدَّم إلا
عبر `/api/download` بعد التحقّق من رمز موقّع تشفيرياً وصالح 72 ساعة. وتُصدَر روابط جديدة
تلقائياً كلما فتح العميل صفحة حسابه، فلا يحتاج إلى مراسلتك عند انتهاء صلاحيتها.

للملفات الكبيرة، ارفعها على تخزين خارجي (Cloudflare R2 / S3) واضبط `DOWNLOAD_BASE_URL`.

## النشر على Vercel

1. ادفع الكود إلى GitHub (تم بالفعل على فرع `claude/law-website-fixes-j3mvil`).
2. على [vercel.com](https://vercel.com) اختر **Add New ▸ Project** واربط المستودع.
3. **مهم:** في إعدادات المشروع اضبط **Root Directory** على `aboelezzlaw`.
4. أضف كل متغيّرات البيئة في **Settings ▸ Environment Variables**.
5. اضغط **Deploy**.
6. من **Settings ▸ Domains** أضف `aboelezzlaw.com` و `www.aboelezzlaw.com`.
7. في لوحة Hostinger، غيّر سجلّات DNS للنطاق إلى ما تعرضه Vercel (سجل `A` و `CNAME`).

بعد ربط النطاق:

- **حدّث `notification_url` في لوحة Paymob** إلى النطاق النهائي.
- تأكّد من ظهور مهمة الـ Cron في **Settings ▸ Cron Jobs** (تُقرأ من `vercel.json`).

### الحد الأدنى من المتغيّرات لموقع يعمل بالكامل

| المتغيّر | لماذا |
|---|---|
| `RESEND_API_KEY` أو `SMTP_HOST` | بدونه لا تصلك إشعارات النماذج — **إجباري** |
| `DATABASE_URL` | لوحة الحساب وسجلّ الطلبات ومنع الحجز المزدوج |
| `AUTH_SECRET` | توقيع جلسات العملاء |
| `DOWNLOAD_SECRET` | توقيع روابط تحميل المنتجات الرقمية |
| `CRON_SECRET` | حماية محرّك تجديد الاشتراكات |
| `ULTRAMSG_*` أو `TELEGRAM_*` | إشعار فوري على هاتفك (موصى به بشدّة) |
| `BANK_TRANSFER_DETAILS` | وسيلة دفع تعمل فوراً بلا حساب بوابة |

> ### ⚠️ أسعار المتجر
> الأسعار الحالية منقولة من متجرك القديم وأنت ذكرت أنها **أقل من أسعارك الفعلية**.

> الأسعار تُقرأ من هذا الملف **على الخادم** عند الدفع، فلا يستطيع أي عميل التلاعب بها من متصفّحه.

## الأمان — ما هو مطبَّق فعلياً

- **الأسعار تُحسب على الخادم** من الكتالوج، لا تُؤخذ من المتصفّح إطلاقاً (مُختبَر).
- **الجلسات موقّعة بـ HMAC** ولا تُخزَّن؛ كعكة مزوّرة تُرفض ولا تمنح أي وصول (مُختبَر).
- **دخول بلا كلمات مرور** — لا شيء يُسرق إن اختُرقت القاعدة.
- **استعلامات الحساب مقيّدة بالبريد داخل الاستعلام نفسه**، فلا يصل عميل إلى بيانات غيره.
- **قيد فريد في القاعدة يمنع الحجز المزدوج** — لا فحص في الكود وحده يمكن أن يتجاوزه طلبان
  متزامنان.
- **مسار الـ Cron محميّ بسرّ** ويرفض كل استدعاء بدونه (مُختبَر).
- **التنفيذ بعد الدفع آمن عند التكرار** — إعادة إرسال البوابة للإشعار لا تُكرّر التسليم.
- **اشتراك PayPal يُتحقَّق من حالته لدى PayPal** لا من معلَمة الرابط.
- **توقيع HMAC** على webhook الـ Paymob مع مقارنة ثابتة الزمن — يرفض الإشعارات المنتحَلة.
- **روابط تحميل موقّعة** ومحدودة المدة (72 ساعة) للمنتجات الرقمية.
- **حقل فخّ (honeypot)** مخفي في كل نموذج، يردّ نجاحاً صامتاً على الآليات.
- **حدّ معدّل** لكل عنوان IP على كل نموذج.
- **تحقّق من المدخلات** بـ Zod على الخادم — لا يُوثق بأي تحقّق في المتصفّح وحده.
- **لا تُخزَّن بيانات بطاقات** على هذا الموقع في أي مرحلة.
- ترويسات أمان (`X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`).

## ما لم يُنجَز بعد

بيان صريح بما هو خارج هذا التسليم:

1. **النسخة الإنجليزية.** الموقع القديم كان ثنائي اللغة. هذه النسخة عربية بالكامل.
   إضافة الإنجليزية تحتاج `next-intl` وإعادة هيكلة المسارات إلى `/[locale]/…` — عمل منفصل.
2. **لوحة تحكم للمكتب** (لا للعميل). لوحة العميل جاهزة، لكن إدارة الطلبات من جانبك تتم
   عبر البريد وواتساب حالياً. لوحة إدارية تحتاج صلاحيات ونظام أدوار.
3. **تجديد Paymob التلقائي.** التجديد التلقائي مبنيّ على PayPal. Paymob يدعم الاشتراكات
   المتكرّرة، ويمكن إضافتها بنفس نمط `paypal.ts` بعد اعتماد حسابك ومعرفة معرّفات خططك.
4. **كتاب الزكاة** — المنتج معلَّم «قريباً» حتى ترفع ملفه. لا أستطيع تأليف كتابك نيابةً عنك.
5. **مراجعة نماذج العقود.** النماذج مصاغة صياغة مهنية لكنها تحتاج مراجعتك واعتمادك قبل
   البيع — راجِع التنبيه في قسم المنتجات الرقمية.
